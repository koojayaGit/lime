# ZERO TO ONE --- 구현 방향

## 1. 개발 방향 요약

ZERO TO ONE은 PC와 모바일에서 함께 사용할 수 있는 반응형 웹앱으로
개발한다. 초기에는 개인 투자 연구소로 사용하되, 향후 지인들도 각자
계정을 만들어 사용할 수 있도록 사용자별 데이터 분리와 권한 구조를
처음부터 고려한다.

개발의 중심은 포트폴리오 수익률 화면이 아니라 **기업 분석과 성장
추적(Research)** 이다.

## 2. 제품 및 플랫폼 방향

### 2.1 반응형 웹앱 + PWA

-   PC와 스마트폰에서 동일한 서비스에 접속한다.
-   화면 크기에 따라 레이아웃과 정보 밀도를 조정한다.
-   PWA 적용을 통해 지원되는 기기에서는 홈 화면에 설치할 수 있도록 한다.
-   모바일과 PC에서 동일한 계정 및 데이터를 사용한다.
-   네트워크가 불안정한 상황을 고려해 일부 화면의 읽기 전용 캐시를
    검토한다.
-   푸시 알림은 브라우저·운영체제별 지원 여부와 실제 기기 테스트를 거쳐
    제공한다.

**PC 우선 사용 경험** - 기업 비교와 상세 리서치에 적합한 넓은 화면 -
정렬·필터가 가능한 기업 목록과 데이터 테이블 - 분석 내용, 차트,
타임라인을 함께 확인할 수 있는 화면

**모바일 우선 사용 경험** - 간결한 대시보드 - 관심종목 및 기업 정보 빠른
조회 - 알림 확인과 주요 이벤트 확인 - 간단한 메모 및 연구 기록 입력

### 2.2 디자인

-   라이트 모드와 다크 모드를 모두 지원한다.
-   정보의 위계와 가독성을 우선한다.
-   장기 투자 연구 도구에 어울리는 차분하고 전문적인 디자인을 지향한다.
-   불필요한 장식이나 단기 매매를 유도하는 시각 효과는 최소화한다.

## 4. 데이터 구조 설계 방향

### 4.1 기업과 상장 종목 분리

기업(Company)과 주식·증권(Security)을 별도의 데이터 객체로 관리한다.

-   하나의 기업이 여러 시장이나 거래소에 상장될 가능성을 고려한다.
-   기업 분석은 상장 종목과 분리해 보유하지 않은 기업도 등록할 수 있도록
    한다.
-   포트폴리오의 보유 내역은 기업 자체가 아니라 실제 거래 가능한 증권과
    연결한다.

### 4.2 공통 데이터와 개인 데이터 분리

**공통 데이터 후보** - 기업 기본정보 - 상장 시장 및 티커 정보 - 공개된
공시·재무·뉴스 등 외부 데이터

**사용자별 비공개 데이터** - 관심종목 및 발굴 메모 - 기업별 개인 평가와
점수 - 투자 가설 및 검증 기록 - 포트폴리오와 거래 내역 - 알림 조건 및
알림 설정 - 개인 연구 노트

초기에는 한 명이 사용하더라도 사용자 ID를 기준으로 개인 데이터를
설계한다. 향후 지인이 가입하더라도 서로의 포트폴리오와 투자 기록이
노출되지 않아야 한다.

### 4.3 보안 원칙

-   Supabase Auth로 사용자를 인증한다.
-   개인 데이터 테이블에는 사용자 식별자를 둔다.
-   RLS 정책으로 본인 데이터만 조회·수정·삭제할 수 있도록 한다.
-   서로 다른 테스트 계정으로 데이터 격리 여부를 검증한다.
-   API 키와 비밀번호는 환경변수로 관리하고 Git 저장소에 커밋하지
    않는다.
-   데이터 내보내기와 백업·복원 방안을 마련한다.

## 5. 알림 시스템 구현 방향

관심종목으로 등록한 기업에 대해 사용자가 지정한 조건이나 중요한 기업
이벤트를 알릴 수 있도록 한다.

### 알림 유형 후보

-   목표 가격 도달
-   사용자가 설정한 등락률 도달
-   실적 발표 및 실적 공시
-   주요 공시
-   기업 관련 뉴스
-   기술 개발, 제품 출시, 계약, 고객 확보, 상용화 등 성장 이벤트
-   사용자가 직접 정의한 조건

### 알림 전달 채널

1.  앱 내부 알림센터
2.  PC 브라우저 알림
3.  모바일 푸시 알림(PWA 및 기기 지원 범위 내)
4.  추후 이메일 알림 검토

사용자가 알림 종류별로 수신 여부를 설정할 수 있어야 한다. 알림에는
가능한 경우 출처와 발생 시점을 표시한다. 외부 데이터 제공처의 지연이나
누락 가능성도 고려한다.

## 6. Git 및 개발 운영

### 기본 도구

-   VS Code
-   OpenAI Codex
-   Git
-   GitHub Private Repository

### 브랜치 운영안

-   `main`: 안정적으로 동작하는 버전
-   `develop`: 개발 기능 통합
-   `feature/*`: 개별 기능 개발 브랜치

### 개발 절차

1.  기능 단위로 작업 범위를 정의한다.
2.  기능 브랜치에서 구현한다.
3.  저장·수정·삭제 및 오류 상황을 테스트한다.
4.  기존 기능에 영향을 주지 않는지 회귀 테스트한다.
5.  검증된 변경사항을 통합한다.
6.  안정 버전은 태그 등으로 보존한다.

`.gitignore`를 설정하고 환경변수 파일, 비밀키, 인증정보, 개인 데이터가
저장소에 포함되지 않도록 한다.

## 7. 단계별 개발 로드맵

### 1단계 --- 기반 구축

-   React 프로젝트 및 기본 폴더 구조
-   공통 레이아웃과 메뉴
-   라이트·다크 모드
-   반응형 화면
-   로그인 및 기본 데이터 구조
-   기업 등록·조회·수정·삭제

### 2단계 --- Research

-   기업별 5개 평가 영역
-   Innovation Score와 Execution Score
-   성장 단계 관리
-   평가 근거와 변경 이력

### 3단계 --- Investment Thesis

-   최초 투자 가설 작성
-   성공 조건과 위험 요인
-   가설 무효화 조건
-   검증 기록 및 변경 이력

### 4단계 --- Timeline & Monitoring

-   실적, 공시, 기술개발, 계약, 고객 확보 등 이벤트 기록
-   기업별 타임라인
-   관심종목 모니터링과 알림 설정

### 5단계 --- Portfolio

-   한국 및 미국 주식
-   수량, 평균 매입가, 거래 내역
-   평가금액과 손익
-   환율 및 배당 관리

### 6단계 --- 데이터 자동화 및 확장

-   주가·환율 데이터 연동
-   공시·재무 데이터 연동
-   뉴스 및 기업 이벤트 수집
-   AI 분석 보조
-   사용자 초대 및 선택적 분석 공유

## 8. 데이터 정확성 원칙

-   API가 연결되지 않았거나 데이터가 갱신되지 않은 경우 실시간 데이터인
    것처럼 표시하지 않는다.
-   가격·환율·재무 데이터에는 출처와 기준 시점을 기록한다.
-   자동 수집 데이터와 사용자가 직접 입력한 데이터를 구분한다.
-   AI가 생성한 분석에는 참고 출처와 분석 시점을 남길 수 있도록
    설계한다.
-   자동 분석 결과가 사용자의 투자 판단을 대체하지 않도록 한다.

## 9. 개발 원칙

-   작은 기능 단위로 구현하고 매 단계 작동 여부를 확인한다.
-   핵심 데이터의 생성·조회·수정·삭제를 우선 검증한다.
-   오류가 발생해도 기존 데이터가 손실되지 않도록 한다.
-   초기 개인용 구조를 만들면서 향후 다중 사용자 확장을 막지 않도록
    한다.
-   외부 API가 준비되지 않은 기능은 명확히 미구현 또는 데이터 없음으로
    표시한다.
