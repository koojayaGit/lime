# LIME -- Portfolio 화면 개발 명세서

## 1. 개발 목적

LIME은 단기 매매나 트레이딩보다 장기 성장기업을 발굴하고 보유하며, 투자
판단을 지속적으로 관리하는 개인 투자 연구 앱이다.

Portfolio 화면은 사용자가 현재 보유한 주식과 현금 현황을 한눈에 파악할
수 있도록 구성한다.

핵심 원칙은 다음과 같다.

-   장기 투자자에게 필요한 핵심 정보 중심으로 구성한다.
-   빈번한 매수·매도 거래내역 관리 기능은 초기 버전에서 제외한다.
-   보유 수량과 평균 매입가는 사용자가 직접 입력하고 수정한다.
-   투자 시작 시점은 실제 체결일이 아닌 투자자가 판단하는 기준 연월로
    관리한다.
-   현금도 중요한 투자 자산이므로 별도 항목으로 표시하고 전체 자산 비중
    계산에 포함한다.
-   보유 종목의 현재가는 시세 API에서 조회한다. API 연동 전이거나 조회에
    실패한 경우 임의의 실시간 가격을 표시하지 않는다.
-   한국 종목만 보유하면 원화, 미국 종목만 보유하면 달러로 표시한다.
    한국과 미국 종목을 함께 보유하면 원화와 달러 환산 금액을 함께 표시하고,
    표시 순서를 전환할 수 있게 한다.

## 2. 화면 구성

Portfolio 화면은 다음 순서로 구성한다.

1.  Portfolio Summary
2.  Portfolio Allocation
3.  Holdings Table

Portfolio Allocation에는 종목 및 현금별 전체 자산 비중과 주식 평가액 기준의
5단계 성장 분포를 함께 표시한다. 성장 단계별 비중은 현금을 제외한 주식
평가액을 분모로 사용하며, 비중이 큰 단계부터 막대그래프와 범례에 표시한다.

### 2.1 Portfolio Summary

화면 상단에 전체 포트폴리오의 핵심 정보를 표시한다.

  항목                    설명
  ----------------------- ----------------------------------
  Total Portfolio Value   주식 평가금액 합계 + 현금
  Total Return            주식 투자금 대비 주식 평가손익률
  Total Return Amount     주식 평가손익 금액

표시 예시:

-   Total Portfolio Value: ₩128,500,000
-   Total Return: +28.5%
-   Total Return Amount: +₩28,500,000

위 수치는 UI 예시용 가상 데이터다. 실제 구현에서는 저장된 보유 데이터와
현재가를 바탕으로 계산한다.

**수익률 계산 원칙**

초기 버전에서는 전체 수익률을 주식 투자 성과 기준으로 계산한다. 현금은
포트폴리오 총자산과 비중에는 포함하지만, 주식 투자 수익률 계산에는
포함하지 않는다.

-   주식 투자원금 합계 = 각 주식의 보유 수량 × 평균 매입가 합계
-   주식 평가금액 합계 = 각 주식의 보유 수량 × 현재가 합계
-   Total Return Amount = 주식 평가금액 합계 - 주식 투자원금 합계
-   Total Return (%) = Total Return Amount ÷ 주식 투자원금 합계 × 100

현금만 보유하고 주식 투자원금이 0인 경우 Total Return은 `—`로 표시한다.
포트폴리오 총자산과 비중은 모든 보유 종목의 현재가 및 필요한 환율을
조회한 경우에만 계산한다. 하나라도 조회할 수 없으면 총자산·수익률·비중을
확정값처럼 표시하지 않고 `—`와 계산 보류 사유를 보여준다. 개별 종목에서
조회에 성공한 가격과 행별 계산 결과는 확인할 수 있다.

#### 표시 통화 및 환산

- 한국 종목만 보유한 경우 기준 표시는 KRW, 미국 종목만 보유한 경우 기준
  표시는 USD로 한다.
- 한국과 미국 종목을 모두 보유한 경우 KRW 환산값을 기본으로 표시하고,
  바로 아래에 USD 환산값을 함께 표시한다.
- 혼합 포트폴리오에는 KRW/USD 표시 전환 컨트롤을 제공한다. 전환하면 두
  통화의 표시 순서를 바꾸며, 요약·종목별 환산 금액에 일관되게 적용한다.
- 환산에는 기존 Market 화면에서 사용하는 USD/KRW 환율 데이터를 재사용한다.
  환율을 가져오지 못한 경우 환산 금액은 `—`로 표시하고 원래 통화 금액은
  확인할 수 있게 한다.
- CASH 잔액은 입력 통화를 함께 저장한다. 종목 통화와 동일하게 포트폴리오
  통화로 환산해 총자산 및 비중을 계산한다.

### 2.2 Portfolio Allocation

전체 포트폴리오에서 각 주식과 현금이 차지하는 비중을 가로형 누적
막대그래프와 범례로 표시한다.

포함 항목: - 각 보유 종목 - CASH

비중 계산: - 개별 종목 비중(%) = 해당 종목 평가금액 ÷ Total Portfolio
Value × 100 - 현금 비중(%) = 현금 잔액 ÷ Total Portfolio Value × 100 -
Total Portfolio Value = 주식 평가금액 합계 + 현금 잔액

모든 종목 비중과 현금 비중의 합계는 원칙적으로 100%가 되어야 한다. 화면
표시 시 반올림으로 인해 합계가 100%와 조금 다를 수 있다.

현금이 없는 경우에도 CASH 범례 또는 항목은 유지한다. 현재가나 환율 조회가 불완전하면 CASH를 포함한 비중 계산 전체를 보류하며, 일부 종목만으로 비중 합계를 재조정하지 않는다.

### 2.3 Holdings Table

보유 종목과 현금을 하나의 표에서 확인할 수 있도록 한다.

컬럼 순서:

    순서 컬럼명             설명                        데이터 방식
  ------ ------------------ --------------------------- -------------------------------------
       1 Company            기업명 및 티커              종목 데이터
       2 Growth Stage       씨앗주~열매주 성장 단계      사용자 선택
       3 Portfolio Weight   전체 포트폴리오 대비 비중   자동 계산
       4 Shares             현재 보유 주식 수           사용자 직접 입력
       5 Avg. Cost          평균 매입가                 사용자 직접 입력
       6 Current Price      현재 주가                   시세 API 조회
       7 Invested           투자 원금                   자동 계산
       8 Market Value       현재 평가금액               자동 계산
       9 Return             수익률                      자동 계산
      10 Since              투자 시작 기준 연월         사용자 직접 입력

#### 주식 행 계산 규칙

-   Invested = Shares × Avg. Cost
-   Market Value = Shares × Current Price
-   Return Amount = Market Value - Invested
-   Return (%) = Return Amount ÷ Invested × 100
-   Portfolio Weight (%) = Market Value ÷ Total Portfolio Value × 100
-   성장 단계별 비중(%) = 해당 단계 종목의 평가금액 합계 ÷ 전체 주식
    평가금액 합계 × 100. 현금은 성장 단계별 비중에서 제외한다.
-   성장 단계가 지정되지 않은 기존 보유 종목은 `미분류`로 표시하고 해당
    비중도 별도로 보여준다.

Invested와 Market Value는 종목 통화 기준으로 계산한 뒤, 전체 포트폴리오
기준 통화로 환산해 합산한다. 앱에 기준 통화 설정이 이미 있다면 해당
설정을 따른다. 한국·미국 종목 혼합 시 위의 표시 통화 규칙을 적용한다.
환율 데이터가 없으면 환산값을 임의로 만들지 않는다.

#### Since 입력 규칙

-   날짜 전체가 아닌 연월만 입력한다.
-   저장 형식은 `YYYY-MM` 또는 프로젝트의 기존 날짜 형식에 맞춘다.
-   화면 표시는 `YYYY.MM` 형식으로 한다.
-   예: `2023.06`, `2024.02`, `2025.03`
-   의미: 실제 최초 체결일이 아니라 투자자가 정한 투자 시작 기준
    연월이다.

## 3. CASH 행

현금은 주식 종목과 구분되는 특별 행으로 Holdings Table 하단에 표시한다.

  컬럼               표시 규칙
  ------------------ ---------------------
  Company            CASH
  Portfolio Weight   현금 비중 자동 계산
  Shares             `—`
  Avg. Cost          `—`
  Current Price      `—`
  Invested           `—`
  Market Value       현금 잔액
  Return             `—`
  Since              `—`

현금 잔액과 통화(KRW 또는 USD)는 사용자가 직접 입력하고 수정한다.

-   현금 비중 = 현금 잔액 ÷ Total Portfolio Value × 100
-   현금 잔액이 0이면 Market Value는 `0`, Portfolio Weight는 `0.0%`로
    표시한다.
-   현금은 Total Portfolio Value와 Portfolio Allocation 계산에 반드시
    포함한다.
-   현금은 주식 투자원금 및 주식 수익률 계산에서는 제외한다.
-   현금 행은 현금 잔액이 0이어도 항상 표시한다.

현재가 또는 필요한 환율의 조회에 실패하면 현금 비중도 `—`로 표시한다. 현금만 보유한 경우에는 주식 시세 없이 현금의 총자산 및 비중을 계산할 수 있다.

## 4. 데이터 입력 및 수정

초기 버전에서는 거래내역(매수·매도 체결 기록)을 구현하지 않는다.

사용자가 종목별 현재 보유 현황을 직접 관리할 수 있도록 한다.

종목별 입력/수정 항목:

- 기업명, 티커, 국가, 거래소
- 국가에 따라 정해지는 거래 통화(KRW 또는 USD)
- 보유 수량(Shares), 평균 매입가(Avg. Cost)
- 성장 단계(씨앗주·새싹주·성장주·기둥주·열매주)
- 투자 시작 기준 연월(Since)

현금 입력/수정 항목: - 현금 잔액 - 현금 통화(KRW 또는 USD)

현재가는 티커와 거래소를 기준으로 시세 API에서 조회하며, 종목별 통화와
조회 시각 및 데이터 출처를 표시한다. 조회 중에는 로딩 상태, 조회 실패나
지원되지 않는 종목은 `조회 불가` 또는 `—`로 표시한다. 사용자가 현재가를
수동 입력하거나 API 조회 결과를 임의 값으로 대체하지 않는다.
현재가는 10분 간격으로 갱신한다. 미국 종목은 기존 Finnhub 서버 경로,
국내 종목은 Yahoo Finance 시세 경로를 사용한다. 환율은 Market 화면에서
사용하는 USD/KRW 데이터를 재사용한다.

종목 추가, 수정, 삭제가 가능해야 한다. 기존 앱의 데이터 저장 방식과
컴포넌트 구조를 우선 재사용한다.

추후 거래내역 기능을 추가할 가능성을 고려해 데이터 구조를 지나치게
복잡하게 만들지는 않되, 보유 수량과 평균 매입가를 독립적으로 수정할 수
있도록 한다.

## 5. UI/UX 요구사항

-   기존 LIME 디자인 시스템과 색상, 타이포그래피, 여백을 유지한다.
-   상단에 전체 자산과 수익률을 간결하게 표시한다.
-   Portfolio Allocation은 전체 자산의 가로형 누적 막대그래프와 종목별
    범례, 주식 평가액 기준의 성장 단계별 비중 그래프를 표시한다.
-   Holdings Table은 데스크톱에서 표 형태로 보여준다.
-   모바일에서는 가로 스크롤 또는 반응형 레이아웃을 적용해 모든 컬럼을
    확인할 수 있게 한다.
-   수익률은 양수와 음수를 색상으로 구분한다.
-   현금 행은 일반 주식 행과 시각적으로 구분하되 동일한 표 안에
    배치한다.
-   숫자는 천 단위 구분 기호를 사용한다.
-   통화 기호와 소수점 자릿수는 종목 통화 및 기존 앱 규칙을 따른다.
-   데이터가 없는 경우 `0`, `0.0%`, `—` 등을 구분해 표시한다.

계산한다. 서로 다른 통화의 금액을 합산할 때는 기준 통화 환산이 필요하다.

## 7. 구현 및 검증 체크리스트

-   [ ] Portfolio Summary에 Total Portfolio Value 표시
-   [ ] 주식 투자 성과 기준 Total Return 및 손익 금액 계산
-   [ ] Portfolio Allocation에 개별 주식과 CASH 포함
-   [ ] Holdings Table에 지정된 10개 컬럼 표시
-   [ ] Holdings Table에 성장 단계 표시 및 추가·수정 폼에서 단계 선택
-   [ ] 성장 단계별 주식 평가액 비중 표시, 미분류 기존 종목 포함
-   [ ] 종목별 Shares, Avg. Cost, Since 직접 입력 및 수정
-   [ ] 종목 추가 및 삭제 기능 정상 동작
-   [ ] Current Price를 시세 API에서 조회하고 통화·출처·조회 시각 표시
-   [ ] API 조회 중·실패·미지원 상태를 구분하고 가짜 가격을 표시하지 않음
-   [ ] 하나라도 현재가 또는 필요한 환율을 조회하지 못하면 총자산·수익률·전체 비중 계산 보류
-   [ ] 일부 조회 성공 종목만 기준으로 비중 합계를 임의 재조정하지 않음
-   [ ] 한국 종목만 보유 시 KRW, 미국 종목만 보유 시 USD로 표시
-   [ ] 한국·미국 혼합 보유 시 KRW 및 USD 환산값을 함께 표시하고 순서 전환
-   [ ] 환율 조회 실패 시 환산값을 임의로 만들지 않음
-   [ ] CASH 잔액 직접 입력 및 수정
-   [ ] CASH 행은 잔액이 0이어도 항상 표시
-   [ ] 현금 비중이 전체 자산 비중 계산에 포함
-   [ ] 현금은 주식 수익률 계산에서 제외
-   [ ] 모바일 및 데스크톱 화면에서 표 확인 가능
-   [ ] 데이터가 없거나 0으로 나누는 상황에서 오류 없이 표시
-   [ ] 비중 합계가 반올림 오차를 제외하고 100%에 수렴

Portfolio 테이블은 사용자별 `portfolio_holdings` 및 `portfolio_cash`에 저장한다.
초기 SQL Editor 설정은 `supabase/setup_portfolio.sql`, CLI 적용은 날짜순
마이그레이션을 사용한다. 기존 테이블에는 `supabase/setup_portfolio.sql`을
다시 실행하거나 `20261111000000_add_portfolio_growth_stage.sql`을 적용해 성장
단계 컬럼을 추가한다.

## 8. 구현 현황 및 주요 파일

- Portfolio 화면과 보유 종목 추가·수정·삭제: `src/features/portfolio/PortfolioView.tsx`
- 평가액·수익률·전체 비중·성장 단계별 비중 계산: `src/features/portfolio/types.ts`
- Portfolio 저장 및 계정별 Realtime 동기화: `src/app/App.tsx`, `src/lib/supabase.ts`
- 화면 스타일: `src/styles/portfolio.css`, `src/styles/dark-theme.css`
- Portfolio 테이블 및 RLS 정책: `supabase/setup_portfolio.sql`
- 초기 테이블 마이그레이션: `supabase/migrations/20261110000000_create_portfolio.sql`
- 성장 단계 컬럼 추가 마이그레이션: `supabase/migrations/20261111000000_add_portfolio_growth_stage.sql`

보유 종목과 현금은 로그인 사용자별로 저장하고 RLS로 분리한다. 기존 데이터에
성장 단계가 없으면 `미분류`로 표시한다. 단계별 비중은 종목별 현재가와 필요한
환율을 모두 가져온 뒤 계산하며, 결과는 큰 비중 순으로 정렬한다.

## 9. Codex 작업 지시

현재 프로젝트의 폴더 구조, 기술 스택, 기존 Portfolio 관련 코드와 데이터
저장 방식을 먼저 확인한다.

그 다음 이 명세서에 맞춰 기존 구조를 최대한 재사용해 Portfolio 화면을
구현한다.

작업 시 유의사항: 1. 기존 Dashboard, Companies 등 다른 화면의 기능과
디자인을 임의로 변경하지 않는다. 2. 기존 데이터 구조나 저장 방식을
확인하지 않고 새 구조를 중복 생성하지 않는다. 3. 실제 API 연동이 되지
않은 가격은 임의의 실시간 데이터처럼 표시하지 않는다. 4. 계산 로직은 UI
컴포넌트와 분리해 재사용 및 테스트가 가능하도록 구성한다. 5. 구현 후
종목 추가·수정·삭제, 현금 수정, 비중 계산, 0원 처리, 모바일 레이아웃을
직접 검증한다. 6. 완료 후 변경한 파일, 주요 구현 내용, 미완료 사항을
요약해 보고한다.
