# LIME 프로젝트 폴더 구조

> Long-term · Insight · Moat · Evolution\
> 장기 성장기업 발굴과 투자 연구를 위한 개인용 플랫폼

## 1. 설계 방향

LIME은 단순한 주식 보유 현황 관리 앱이 아니라 다음 기능을 갖춘 장기
성장투자 연구 플랫폼을 목표로 한다.

-   관심기업 발굴 및 워치리스트 관리
-   기업의 사업·제품·기술·경쟁우위 분석
-   경영진, 성장전략, 연구개발 및 재무 분석
-   기업별 투자 아이디어와 투자 근거 기록
-   국내·미국 주식 포트폴리오 관리
-   보유 수량, 평균 매입가, 평가금액 및 손익 관리
-   향후 사용자별 계정과 데이터 분리를 지원할 수 있는 확장성

기본 기술 스택은 기존 구조의 전제를 유지한다.

-   프론트엔드: React + TypeScript + Vite
-   백엔드/DB: Supabase (도입 단계에서 확정)
-   테스트: Unit / Integration / E2E
-   버전 관리: Git
-   UI: 반응형 웹, 향후 PWA 확장 고려

## 3. 주요 구조 설계 원칙

각 화면의 상세 동작과 데이터 출처는 화면별 문서에 기록한다. [Dashboard](011_Dashboard.md), [Discovery](013_Discovery.md), [Research](014_Research.md) 문서를 참고한다.

### 3.1 기능별 독립 관리

`features/` 아래에서 실제 서비스 기능을 독립적으로 관리한다.

예를 들어 기업 분석 기능은 다음과 같이 구성한다.

-   `components/`: 기업 분석 화면에서 사용하는 UI
-   `hooks/`: 분석 화면의 상태와 동작
-   `services/`: 분석 데이터 조회·저장
-   `types/`: 분석 기능 전용 타입
-   `pages/`: 분석 기능의 페이지

이렇게 하면 기업 분석 기능을 수정할 때 관련 파일을 한곳에서 찾기 쉽다.

### 3.2 공통 코드와 기능 전용 코드 구분

-   `src/components/`: 여러 기능에서 재사용하는 범용 UI
-   `src/features/{기능}/components/`: 해당 기능에서만 사용하는 UI
-   `src/hooks/`: 여러 기능에서 사용하는 공통 Hook
-   `src/features/{기능}/hooks/`: 특정 기능 전용 Hook
-   `src/services/`: 여러 기능이 공유하는 외부 서비스 연결
-   `src/features/{기능}/services/`: 특정 기능의 데이터 처리

처음부터 모든 폴더와 파일을 만들 필요는 없다. 실제 코드가 생길 때
추가한다.

### 3.3 pages와 router의 역할

-   각 기능의 `pages/`는 실제 화면을 정의한다.
-   `app/router.tsx`는 URL과 페이지를 연결한다.
-   `layouts/`는 페이지들이 공유하는 화면 틀을 제공한다.

프로젝트 규모가 작다면 페이지 파일을 기능 폴더에 바로 두어도 된다.
별도의 `src/pages/`를 중복해서 만들 필요는 없다.

### 3.4 상태 관리

-   서버에서 가져오는 데이터와 화면의 임시 상태를 구분한다.
-   전역 공유가 필요한 상태만 `stores/`에 둔다.
-   특정 기능에서만 쓰는 상태는 해당 기능의 Hook 또는 컴포넌트에서
    관리한다.
-   서버 데이터 캐싱 라이브러리를 도입한다면 전역 상태 저장소와 역할이
    겹치지 않도록 한다.

### 3.5 데이터베이스와 사용자 확장성

초기에는 개인용으로 운영하더라도 데이터 모델은 향후 여러 사용자를 지원할
수 있게 설계한다.

-   사용자 계정과 인증
-   사용자별 포트폴리오
-   사용자별 관심종목
-   사용자별 기업 분석 및 투자 기록
-   데이터 접근 권한과 사용자 간 데이터 분리

Supabase를 사용한다면 테이블의 사용자 소유 관계와 RLS(Row Level
Security) 정책을 함께 설계한다.

## 4. LIME 핵심 기능과 폴더 연결

  핵심 기능    담당 폴더               주요 역할
  ------------ ----------------------- --------------------------------
  대시보드     `features/dashboard/`   투자 현황 요약
  기업 발굴    `features/discovery/`   새로운 성장기업 탐색
  기업 연구    `features/research/`    사업·기술·경쟁우위·경영진 분석
  포트폴리오   `features/portfolio/`   보유 종목과 수익률 관리
  관심종목     `features/watchlist/`   관찰 기업과 알림 관리
  설정         `features/settings/`    계정 및 앱 환경 설정

## 5. 기존 구조에서 변경한 핵심 사항

1.  프로젝트 루트 이름을 `zero-to-one/`에서 `lime/`으로 변경한다.
2.  기존에 별도로 제시했던 `research/` 디렉터리를
    `src/features/research/`로 통합한다.
3.  `features/`를 중심으로 기능별 코드를 독립적으로 관리한다.
4.  전역 공통 컴포넌트와 기능 전용 컴포넌트의 책임을 구분한다.
5.  `src/pages/`를 별도로 두지 않고 기능별 `pages/`에서 화면을 관리한다.
6.  데이터 모델과 화면 설계 문서를 `docs/`에 추가한다.
7.  PWA 관련 파일은 실제 PWA 적용 단계에서 추가한다.
8.  초기에는 필요한 폴더만 생성하고, 기능이 늘어날 때 확장한다.

## 6. 구현 시 주의사항

-   이 문서는 권장 구조이며, 모든 디렉터리를 초기부터 생성해야 한다는
    뜻은 아니다.
-   `services/`, `stores/`, `lib/` 등은 실제 도입 기술과 구현 범위에
    맞게 조정한다.
-   주가 데이터 제공처와 실시간 시세 API는 별도로 선정해야 한다.
-   API 키와 비밀값을 Git에 커밋하지 않는다.
-   테스트는 각 기능의 복잡도에 맞춰 추가한다.
-   새로운 폴더 구조나 기술 선택을 변경할 때는 `docs/decisions/`에 결정
    이유를 기록한다.
